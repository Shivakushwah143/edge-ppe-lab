# Registry tag hygiene verification (release_status must not contradict the champion alias)
timestamp: 2026-09-22T10:56:12Z
host: Linux 6.18.33.2-microsoft-standard-WSL2 x86_64 GNU/Linux | python: Python 3.12.3

Environment: MLflow 3.16.0 at http://127.0.0.1:5000, registered model edge-ppe-detector, tracked in SQLite.

## 1. What was fixed

scripts/set_champion.py is the only promotion path. Before this fix it set release_status=champion
on the newly promoted version but never cleared that tag from the previously promoted version, so
BOTH v1 and v2 carried release_status=champion while the mutable champion ALIAS pointed at v1 only.

The promotion logic now, in order:
  1. reads the current champion alias target (the previous champion);
  2. demotes every other version that still claims release_status=champion to release_status=qualified
     (a version can only have reached champion through the parity gate, so "qualified" is accurate);
  3. points the champion ALIAS at the promoted version and tags it release_status=champion.
Aliases + version tags only - no deprecated MLflow stages are used anywhere.

## 2. Before the fix (contradiction present)

$ python -c "<MlflowClient: alias + all version tags>"

  edge-ppe-detector version 1 release_status='champion' parity_status='passed'
  edge-ppe-detector version 2 release_status='champion' parity_status='passed'
